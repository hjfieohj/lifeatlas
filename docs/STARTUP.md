## 官方资料确认的接入事实

1. `gmail.readonly` 和 `gmail.modify` 都属于 restricted scopes；`gmail.modify` 的能力比归档更宽。应用不能宣称用户只授权了归档。生产后端只开放指定 label 修改操作，不提供任意 Gmail API 代理。[Google scopes](https://developers.google.com/workspace/gmail/api/auth/scopes)
2. 归档通过移除 `INBOX`，恢复通过补回 `INBOX`。每封邮件的标签操作可单独返回结果，不能把整个批次视为一个数据库事务。读取前后核对也不能消除与其他客户端操作间的所有竞态；对象变化时停止或交给用户处理。[messages.modify](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages/modify)
3. 个人用途与开发测试可能适用验证例外；公开服务的受限权限验证以及服务端处理数据时的评估要求，须按具体条件判断，不得将私人原型部署等同 Gmail 公开发布准备完毕。[Restricted scope verification](https://developers.google.com/identity/protocols/oauth2/production-readiness/restricted-scope-verification)
4. 外部用户类型、Testing 发布状态下，包含 Gmail 权限的刷新令牌通常 7 天过期，需处理重连和 `invalid_grant`。[Refresh token expiration](https://developers.google.com/identity/protocols/oauth2#expiration)
5. Google 推荐按功能需要逐步申请额外权限；Web 服务需要自己的客户端 ID、回调和服务端安全配置。[OAuth Web server flow](https://developers.google.com/identity/protocols/oauth2/web-server)
6. Gmail 数据使用必须符合声明的用途与数据政策；处理真实正文前，要先确认模型服务的处理、保留与训练条款。[Workspace user data policy](https://developers.google.com/workspace/workspace-api-user-data-developer-policy)

核实层级：官方文档已查；真实账户、配额、目标地区访问、模型费用均未实测。Jina 匿名 Reader 因 IP 限制失败，改从 Google 官方开发者页面读取，不把检索失败当作接口不可用。

## 建议工程边界

原型使用 TypeScript + Vite，便于快速验证交互和独立测试执行模型。正式应用建议保持 TypeScript，增加服务端 OAuth、持久化数据库、作业队列和模型适配层；待真实依赖验证后选择具体框架与托管。

真实系统必须补齐：用户身份、服务端行级隔离、会话与 CSRF 防护、OAuth state 与回调校验、令牌加密和撤销、服务端确认存储及幂等、作业恢复、供应商限流与重试、数据保留和删除、监控回退。当前客户端规则是可验证的行为原型，不是安全边界。

模型的自报信心不是概率。初版分类先保守保护、基于规则过滤；冲突、缺失或无法解释时进入复核。没有训练/评估集前不展示「99%准确」等数值。
