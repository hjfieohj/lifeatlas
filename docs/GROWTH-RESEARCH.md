# GitHub 经验与本轮落地（2026-10-19）

目标是让记录形成“经历 → 理解 → 尝试 → 反馈 → 再回顾”的连续过程。本轮只借鉴交互和数据组织原则，没有复制外部项目代码，也没有引入依赖。

| 参考 | 可借鉴的经验 | LifeAtlas 本轮落地 |
| --- | --- | --- |
| [Logseq linked references](https://github.com/logseq/logseq/pull/11739) | 让理解可以回到具体来源；引用视图需要可筛选、可返回原文 | 反馈明确选择一次旧尝试；回顾选择具体原始记录；保留版本和摘录，并能打开修改历史 |
| [Monica README](https://github.com/monicahq/monica/blob/main/README.md) | 活动、笔记、任务和后续提醒相互配合，避免记完即止 | 展示近期尝试和关联反馈数量，提供继续回应入口；数量只代表关联条数，不代表行动已完成或有效 |
| [Journiv](https://github.com/journiv/journiv-app) 与 [发布记录](https://github.com/journiv/journiv-app/releases) | 检索、提示和降低记录成本有助于持续使用 | 一次经历只需先写事实；观察等可展开补充。关键词和日期在服务端检索，可找到未加载的旧记录 |

这些是从各项目功能中提取的设计原则，并不表示其采用 LifeAtlas 相同的数据模型。Monica main 标明新版本 beta、4.x 稳定；Journiv 仍属快速迭代项目，不将其所有功能视为已验证的成熟方案。

## 使用方法

1. 在个人成长里选择一个主题。“记录一次经历”先写事情经过，必要时再展开观察、理解与下一步。
2. 从近期尝试或某条记录点击“回应这次尝试”。确认来源，填写实际结果并保存。结果可以是有效、无效或尚未尝试。
3. “做一次阶段总结”选择起止日期，载入材料，再勾选本次依据的记录。写下哪些理解得到印证、哪些需要修正。
4. 在查找栏输入关键词或起止日期，找回旧记录；也可再切换到前后对照。筛选作用于当前主题，导出仍包含完整主题。

## 数据与边界

- 新的 `growth_moments.context` 字段默认为 `{}`，旧记录不自动猜测关联。迁移为 `0002_sloppy_star_brand.sql`；只新增一列，不改写已有正文。旧迁移不得重放。
- 来源由服务端按当前账户、同一主题、有效记录和版本校验。反馈日期不能早于来源日期；有明确关联时必须填写结果。编辑既有反馈不能偷偷更换来源。
- 保存时固定来源的 ID、日期、版本、事件摘录（最多 300 字）、理解摘录（最多 500 字）；反馈另外保留原始尝试全文。以后修改或收起来源，都不会改写这些依据。完整正文从修改历史查看。
- 内容修改生成版本；收起和恢复只增加状态版本，因此某个引用的版本号可能没有独立的正文修订项，固定摘录仍保留。
- 近期尝试最多读取 40 条、展示 4 条；更早的尝试可通过检索找到并回应。改写尝试文字后，反馈数量按该文字对应的已有反馈计数，旧反馈本身仍保留。
- 回顾材料最多读取 3 页（每页 30 条，收起的记录跳过），最多选择 20 条。超过时提示缩小日期区间；改动日期会清除旧选择。材料载入不带入关键词过滤，避免不小心遗漏同一时段的经历。
- 检索为正文的文字包含查询，日期含首尾。不是语义检索，也不会自动判断成长、因果或心理状态。
- 导出包含引用和修订历史。未增加 AI、持久草稿、定时提醒、附件或单独的尝试状态管理；当前仍需手动保存。本机和云端数据库各自独立。

## 验证与收尾结论

39 项自动测试全部通过，其中成长相关 14 项。实际 SQLite 查询覆盖分页检索、日期、跨账户隔离、冻结引用、修改与归档后的计数、拒绝过时来源、重复材料及导出一致性。类型检查和生产构建通过。

浏览器使用既有“演示｜工作与生活的边界（虚构）”主题，仅新增一条明确标记的虚构反馈和一条有三条依据的虚构回顾。走通保存、刷新、检索、展开依据、返回原文、重新载入材料后保留输入及恢复保存按钮。未改动真实个人内容或邮箱。

收尾修正：检索默认展示记录，避免一条结果落入双记录对照空态；载入材料后恢复保存按钮文字；近期尝试列表取消不适用的旧网格，避免文字挤成窄列。界面沿用两套既有皮肤与粒子，没有新视觉资产。

结论：本轮三项改进可以试用。截图证据限实际应用内浏览器的窄屏画面，未声称完成所有设备、所有状态的可访问性验收。长期使用、草稿恢复及真实 Gmail 配置仍待后续。
